# نتایج واقعی آزمون — ۲۵ اکتبر ۲۰۲۶

## آخرین اجرا پس از ادغام Blob خصوصی

این بخش جایگزین وضعیت قدیمی S3 و انتشار ورسل در بخش‌های تاریخی پایین است.

| بررسی | نتیجهٔ اجراشده |
| --- | --- |
| `npm run build` | موفق؛ Compiled successfully و تولید همهٔ routeهای receipt/admin/cron |
| `npm run lint` | موفق، بدون خطا یا هشدار |
| `npm run typecheck` | موفق؛ build نهایی نیز TypeScript را بررسی کرد |
| `npm run test:db` | ۴۸ موفق، صفر خطا و صفر skip |
| `E2E_BASE_URL=http://localhost:3000 npm run test:e2e` | ۱۷ موفق، ۳۵٫۷ ثانیه |
| `npm audit --omit=dev` | صفر آسیب‌پذیری اجرایی |
| migration سوم روی development | موفق؛ ۳۵ جدول، بدون reset داده |
| Preview واقعی با Secret موجود Blob | آپلود PNG خصوصی و دانلود byte-for-byte موفق |
| دسترسی خصوصی Preview | مالک و پزشک با MFA مجاز؛ ناشناس، بیمار دیگر و لینک مستقیم منع شدند |
| metadata و پرداخت | اندازه و SHA-256 صحیح در Neon؛ وضعیت فقط under_review |
| Cron واقعی Preview | بدون مجوز 401؛ با مجوز 200، dryRun=true و deleted=0 |

حذف و retry با mock آزموده شدند؛ حذف واقعی بیمار فعال یا آزمایش نشد. یک نمونهٔ تصویری کوچک ساختگی خصوصی برای ثبت نتیجه باقی ماند؛ نشست‌های آزمایشی باطل و بانک ساختگی غیرفعال شد. آزمون احراز هویت Preview با نشست‌های ساختگی در DB توسعه بود، نه ارسال OTP یا بررسی MFA تعاملی. [گزارش فایل‌ها، تنظیمات و محدودیت‌ها](VERCEL-BLOB.fa.md).

## به‌روزرسانی پس از اتصال Neon

پس از ورود کاربر با حساب مجاز، شاخهٔ development ساخته و هر دو migration روی آن اجرا شدند. آزمون `npm run test:db` با خروجی ۱۴ موفق، صفر ناموفق و صفر skip پایان یافت؛ آزمون DB واقعاً عملیات موقت خواندن/نوشتن و rollback انجام داد. اجرای HTTP متصل نیز هشت بررسی موفق داشت: بارگذاری صفحه با DB، بسته‌بودن رزرو، نیاز به احراز هویت، OTP توسعه و کوکی HttpOnly، منع دسترسی بیمار به مدیریت، replay، CSRF و خروج. رکوردهای مصنوعی آزمون حذف شدند و پیامک واقعی ارسال نشد. lint و typecheck پس از اصلاح اسکریپت‌ها نیز موفق شدند.

جزئیات نصب موجود MCP، فایل‌ها و منابع تغییرکرده در [گزارش اتصال Neon](NEON-SETUP.fa.md) آمده است.

## آزمون‌های اولیه پیش از اتصال Neon

| فرمان                                                 | نتیجه                                                    |
| ----------------------------------------------------- | -------------------------------------------------------- |
| `npm run build`                                       | موفق؛ `Compiled successfully` و تولید مسیرهای App Router |
| `npm run lint`                                        | موفق، بدون خطا یا هشدار                                  |
| `npm run typecheck`                                   | موفق؛ TypeScript strict                                  |
| `npm test`                                            | ۱۳ موفق، صفر ناموفق، یک skip مربوط به پایگاه داده        |
| `E2E_BASE_URL=http://127.0.0.1:3001 npm run test:e2e` | `13 passed (29.5s)` با Chrome واقعی                      |
| `npx drizzle-kit generate`                            | موفق؛ ۳۴ جدول و دو فایل migration محلی                   |
| `npm audit --omit=dev --json`                         | صفر آسیب‌پذیری گزارش‌شده در وابستگی‌های اجرایی           |

نمونهٔ خروجی آزمون واحد:

```text
tests 14
pass 13
fail 0
skipped 1
```

خروجی پایانی آزمون مرورگر:

```text
Running 13 tests using 2 workers
13 passed (29.5s)
```

آزمون‌های مرورگر شامل فارسی و انگلیسی، RTL/LTR در تگ html، تغییر زبان با حفظ مسیر، بازوبسته‌شدن FAQ، انتخاب مشاوره متنی/پیام‌رسان و بررسی فرم، خطای واقعی ورود هنگام نبود DB، محافظت پنل بیمار/مدیر، عدم انتشار مقالهٔ تأییدنشده، نبود کارت یا زمان جعلی، هر شش صفحهٔ خدمات در دو زبان، منوی موبایل، عرض ۳۲۰ پیکسل هر دو زبان، canonical/hreflang/sitemap، هدرهای امنیتی و حفاظت endpoint job هستند.

نمایش صفحه در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ بررسی شد. یک overflow در فارسی ۳۲۰ شناسایی و اصلاح و سپس آزمون خودکار آن موفق شد. تصویر کامل دسکتاپ و موبایل محلی تهیه شد؛ فایل‌ها به‌علت حجم و موقتی بودن در Git قرار نگرفتند. favicon تیره با HTTP 200 بررسی شد.

اولین اجرای آزمون مسیر job روی build قدیمی شکست خورد. پس از ساخت و اجرای خروجی تازه، مجموعهٔ آزمون موفق شد. مدیریت خودکار webServer در ویندوز هنگام teardown متوقف ماند؛ اجرای نهایی با سرور standalone مستقل و E2E_BASE_URL انجام شد و exit code صفر داشت.

نصب اولیه npm با ECONNRESET قطع شد و پس از retry انجام شد. ابزار tsx و Drizzle در sandbox با uv_os_get_passwd خطا دادند؛ اجرای مجاز خارج از sandbox موفق بود. این خطاهای محیطی به‌عنوان موفقیت پنهان نشده‌اند.

## آزمون‌های انجام‌نشده

وضعیت skip پایگاه داده در اجرای اولیه، با اجرای موفق test:db برطرف شده است. ارسال OTP با سرویس پیامک واقعی، رقابت تراکنش‌های رزرو، ذخیره/بازیابی S3، پردازش واریز، SMS retry، MFA مدیر و ماندگاری کامل CMS هنوز آزموده نشده‌اند. آزمون OTP این مرحله از سرویس توسعهٔ بدون ارسال استفاده کرده است.

Docker build، انتشار Vercel، بازیابی backup، آزمون نفوذ، ممیزی کامل دسترس‌پذیری و سنجش Core Web Vitals انجام نشده‌اند. audit وابستگی‌های توسعه چهار مورد moderate در زنجیرهٔ ابزارهای توسعه گزارش کرد؛ گزارش صفر فقط مربوط به وابستگی‌های اجرایی است.
