## تغییر فایل‌ها

- `.neon`: context محلی پروژه و شاخهٔ development ساخته شد. CLI آن را به `.gitignore` اضافه کرد.
- `.env.local`: از الگوی پروژه ساخته شد؛ اطلاعات pooled و direct فقط برای Postgres با `neon env pull --service postgres` دریافت شدند. اطلاعات سرویس‌های نامرتبط دریافت نشد. اتصال‌ها به `sslmode=verify-full` تنظیم شدند. AUTH_SECRET و DEV_OTP_CODE فقط در صورت خالی‌بودن با مقدار تصادفی پر شدند. فایل و رمزها در Git قرار نمی‌گیرند و چاپ نشدند.
- `scripts/check-db.ts` و `scripts/seed.ts`: خطای top-level await در اجرای CommonJS/tsx با تابع async رفع شد؛ مدیریت خطا بدون چاپ credential اضافه شد.
- `scripts/configure-development.mjs`: تنظیم TLS و ساخت secretهای توسعه در صورت نبودن؛ مقدار غیرخالی secret موجود حفظ می‌شود.
- `scripts/test-database.mjs`: اجرای آزمون واقعی DB و آزمون واحد با اتصال شاخهٔ توسعه؛ تست نوشتن، rollback می‌شود.
- `scripts/smoke-development.mjs`: آزمون HTTP ورود توسعه، نشست، منع دسترسی، replay، CSRF و خروج؛ رکوردهای مصنوعی پس از اجرا حذف می‌شوند و SMS واقعی ارسال نمی‌شود.
- `package.json`: فرمان‌های `dev:configure`، `test:db` و `test:connected` اضافه شدند؛ وابستگی جدیدی نصب نشد.
- `AGENTS.md`: توسط خود Next.js هنگام اولین اجرای next dev تولید شد و برای حفظ راهنمای نسخهٔ فعلی نگه داشته شد.
- README و اسناد وضعیت/آزمون به‌روزرسانی شدند تا مشکل دسترسی Neon را همچنان حل‌نشده معرفی نکنند.

## آزمون و محدودیت

آزمون واحد به‌همراه DB: ۱۴ موفق، صفر ناموفق، صفر skip. آزمون HTTP متصل: هشت بررسی موفق شامل صفحهٔ فارسی با DB، بسته‌ماندن رزرو، نیاز به احراز هویت، OTP آزمایشی و HttpOnly session، منع دسترسی بیمار به مدیریت، جلوگیری از replay، منع تغییر بین‌مبدأ و ابطال نشست پس از خروج.

پیامک واقعی، storage خصوصی رسید، تأیید واریز بانکی، MFA واقعی مدیر و انتشار Vercel همچنان در این مرحله راه‌اندازی یا تأیید نشده‌اند. آماده‌بودن اتصال DB به معنی آماده‌بودن کل سامانه برای پذیرش بیمار واقعی نیست.
